# 福礼社 V1.1 产品基线与变更规则

## 1. 当前唯一基线

唯一可用于开发、测试和验收的方案是仓库根目录的 `福礼社单商户供应链平台V1.1综合方案.html`，其 SHA-256 固定为：

`1153157234D2DCCDF38F0C5E468BD5D93889140153F1C21F7FEBB8FA5316EF92`

`baseline-lock.json`同时冻结19份提示词、方案引用的86个UI资产以及V1.1执行包发布快照。V1.0、0801、V29及更早材料只允许用于追溯，不得作为实现输入或覆盖V1.1。

执行包包含会持续变化的任务状态和证据，因此其初始目录哈希用于审计快照；后续目录哈希变化会告警，但只有在执行包自身校验、版本、方案哈希或结构计数失败时才阻断开发。方案、提示词和正式UI引用发生未批准变化时一律阻断。

## 2. 开始任务前

1. 运行 `./scripts/verify-product-baseline.ps1`。
2. 读取根目录及提示词包的 `AGENTS.md`、当前任务、阶段门禁和最近交接。
3. 确认只有 `nextAllowedTask` 被推进。
4. 校验失败时保存实际值和差异，不用旧文件“修复”新文件。

## 3. 产品基线变更流程

只有用户明确批准产品口径变化后才能执行：

1. 记录变更原因、批准内容、旧方案哈希和受影响章节。
2. 对主体、资金、价格、订单、配送、结算、权限、数据和外部系统做影响分析。
3. 先形成新版本方案，不覆盖旧文件；完成相关章节的横向一致性检查。
4. 同步更新提示词、字段字典、状态机、权限矩阵、OpenAPI/DTO/错误码、迁移和页面映射。
5. 同步更新P0验收、任务台账、自动化测试、人工验收和回滚方案。
6. 重新计算方案、提示词、正式UI引用及执行包发布信息，更新锁文件。
7. 对受影响的既有实现重新运行失败测试、focused tests和适用的完整质量链；过期证据降回 `NOT_EXECUTED`。
8. 经人工确认后才把新版本标记为 `FROZEN`。

任一同步项未完成时只能标记为草案，不得继续受影响开发。

## 4. 不属于产品基线变更的事项

以下执行状态可以在不改变产品基线哈希的情况下追加：任务状态、负责人、分支、提交、PR、CI运行、测试时间、证据链接和外部阻塞。它们仍必须保留历史，不能覆盖已确认的证据。

实现技术细节只有在不改变经营主体、资金责任、数据归属、用户结果和P0验收的前提下才可由开发任务决定。无法确定是否改变业务结果时必须停止并请求用户判断。

## 5. 失败与恢复

- 方案哈希、提示词树哈希或正式UI引用树哈希不一致：阻断受影响任务，报告差异。
- 旧方案被指定为当前方案：立即拒绝。
- 执行包自检失败：只修复执行状态/证据同步问题，不回退产品方案。
- 获批变更尚未同步完：保留当前冻结基线，变更材料标记为草案。
- 回滚只通过版本化提交或恢复经验证的备份完成，不使用破坏性Git命令覆盖用户文件。

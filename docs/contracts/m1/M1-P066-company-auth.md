# M1-P066 公司后台登录与职能账号选择实现合同

## 范围

- 只实现 API-003、API-004、PAGE-001 与 PAGE-002；不实现 M1-P067 的各职能工作台，也不进入 M2。
- 公司后台使用独立登录入口，不提供公众注册。登录身份由服务端解析，客户端不能提交 `companyId`、`userId` 或 `functionalAccountId` 改变归属。
- 一个有效职能账号且无需二次验证时直接签发会话；多个账号或需要二次验证时，只返回服务端列出的账号与短期选择 nonce。
- 每个有效会话只绑定一个 `functionalAccountId`。选择 nonce 只能绑定一个账号；同账号重放保持幂等，改选其他账号返回冲突。同一 `userId + requestId` 的选择记录首次创建后不可重置，登录重试不能清除已经完成的账号绑定。

## 安全与数据合同

- 原始会话令牌只写入 `Secure`、`HttpOnly`、`SameSite=Strict` 的 `__Host-fulishe-company-admin` Cookie；数据库只保存 SHA-256 哈希，响应、日志和审计均不返回原始令牌。
- 登录账号在审计中只保存 SHA-256 哈希；未知账号与错误凭证统一返回 `AUTH_INVALID`，连续失败达到阈值后返回 `RATE_LIMITED`。
- `CompanyUser`、`AuthSession`、内部选择授权和 `LoginAudit` 由前向迁移创建；登录审计使用数据库触发器拒绝更新与删除。
- 会话签发事务锁定并重新读取 `CompanyUser` 与 `FunctionalAccount` 的权威状态、归属和有效期；列表读取后的停用、撤销或过期必须失败关闭，不能使用服务层的旧快照签发会话。
- 生产凭证校验器和二次验证器在未接入授权身份源时默认失败关闭；测试只通过显式注入的 verifier 验证合同，不创建默认密码或测试账号。

## P0 负向映射

- `NEG-M1-066-01`：不存在公司公众注册路由或页面入口。
- `NEG-M1-066-02`：同一自然人有多个职能账号时不得自动进入任一工作台，必须先选择服务端返回的账号。
- `NEG-M1-066-03`：同一选择上下文不得建立两个不同职能账号会话；同一 requestId 的登录重试不得重置已完成选择；同一自然人的旧活动会话在新会话签发时撤销。
- `NEG-M1-066-04`：停用、撤销、过期或不属于该自然人的账号不可选择；账号在列表校验后、签发前失效也必须失败关闭；客户端伪造 owner 字段在查询前被拒绝。

## 页面与缓存边界

- `/company-admin/login` 是公开但 `noindex`、`no-store` 的独立登录页，不展示注册链接。
- `/company-admin/account-select` 只消费当前浏览器内的待选择上下文；缺少上下文时失败关闭，不允许手工输入账号 ID。
- 参考资产 `01-公司后台登录.png` 的正文内容实际为供应商入驻，与文件名和 PAGE-001 合同不一致；实现以综合方案的公司登录字段为准，该资产只作为色彩与版式参考。

## 环境、风险与回滚

- 本地验证使用注入 verifier、Playwright Chromium 与 Docker 临时 MySQL；真实企业身份源、短信/风控、预发布、生产迁移和正式验收均未执行。
- Vite 生产包仍有大于 500 kB 的既有警告；后续可在不改变本合同的独立性能切片处理。
- 应用代码可按原子提交 `git revert`；已发布迁移不得回改或向后删除，应用回退需保持新增表兼容，后续数据库修正只允许新的前向迁移。
